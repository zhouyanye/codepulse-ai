# 成本估算机制详解

## 概述

CodePulse AI 的成本估算功能通过分析仓库大小、文件数量和类型，预估使用AI服务进行代码分析所需的Token消耗和费用。该功能帮助用户在执行分析前了解可能的成本，避免意外费用。

## 估算原理

### 基础估算方法

成本估算采用双重方法：
1. **基于仓库大小的估算**：根据仓库总大小(MB)估算Token消耗
2. **基于文件类型的详细估算**：根据代码行数、文件类型等进行精确估算

### 仓库大小因子

根据仓库大小采用不同的Token密度：
- 小仓库(<1MB): 800 token/MB
- 中等仓库(1-10MB): 600 token/MB
- 大仓库(10-50MB): 400 token/MB
- 超大仓库(>50MB): 300 token/MB

### 文件类型系数

不同文件类型的Token估算系数：
- 代码文件：1.2 (Python, JavaScript, Java, Go等)
- Markdown文档：1.0
- 纯文本文件：0.8
- 其他类型文件：0.5

## 分析过程开销

除了基础内容估算，系统还会计算分析过程的额外开销：

| 阶段 | 基础开销(token) |
|------|----------------|
| 初始提示词 | 500 |
| 仓库结构分析 | 300 |
| 代码质量分析 | 800 |
| 安全分析 | 1000 |
| 优化建议 | 600 |
| 最终总结 | 400 |

## AI服务定价

### DeepSeek
- 输入：2.0元/M tokens (未命中缓存)
- 输入：0.2元/M tokens (命中缓存)
- 输出：3.0元/M tokens

### Kimi
- 输入：4.00元/M tokens (未命中缓存)
- 输入：1.00元/M tokens (命中缓存)
- 输出：16.00元/M tokens

### 豆包(Doubao)
- 输入：0.80元/M tokens (推理输入)
- 输入：0.08元/M tokens (缓存命中)
- 输出：1.00元/M tokens (推理输出)

### CoStrict模式
- 成本为0，仅使用API数据进行基础评分，不调用AI服务

## 缓存命中率

系统默认使用60%的缓存命中率计算成本，这意味着40%的输入Token按全价计算，60%的输入Token按缓存价格计算。

## 估算示例

对于一个5MB的仓库，包含100个代码文件、20个文档文件：

```
基础估算：
- 仓库大小估算：5MB × 600 token/MB = 3000 tokens
- 代码文件估算：100 × 200 tokens/文件 = 20000 tokens
- 文档文件估算：20 × 400 tokens/文件 = 8000 tokens
- 分析开销：3100 tokens

总估算：34100 tokens

成本估算（DeepSeek）：
- 输入Token（70%）：23870 tokens
  - 缓存命中：14322 tokens × 0.2元/M = ¥0.0029
  - 缓存未命中：9548 tokens × 2.0元/M = ¥0.0191
- 输出Token（30%）：10230 tokens × 3.0元/M = ¥0.0307
- 总计：¥0.0527
```

## 静态扫描开销

如果启用静态扫描，系统会增加额外的Token开销：
- 基础开销：2000 tokens
- 每个代码文件：50 tokens
- 每MB仓库大小：100 tokens

## 成本控制建议

1. **使用CoStrict模式**：对于仅需基础评分的场景，选择CoStrict模式可实现零成本
2. **批量分析优化**：对于多个相似项目，可利用缓存机制降低后续分析成本
3. **成本预估确认**：在执行高成本分析前，通过CLI工具预估成本
4. **合理选择提供商**：根据分析需求和预算选择合适的AI提供商

## CLI成本预估

使用命令行工具预估成本：
```bash
python cli.py estimate https://github.com/user/repo --provider deepseek
```

该命令将显示详细的成本估算信息，包括预估Token数量、成本和分析时间。
